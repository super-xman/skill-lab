# 架构与生成配方

## 系统边界

浏览器提供 JavaScript、WebGL2、Web Audio、输入、字体；Three.js 提供场景、几何、材质和渲染基础。游戏自己实现规则、内容生成和有预算的画面效果。开发期可使用 npm，成品不需要网络依赖。不要复制参考附件里的引擎代码；从可信包源引入并保留许可。

建议模块：`core`（时间/事件/随机数）、`render`、`materials`、`geometry`、`level`、`input`、玩法规则与状态、`fx`、`audio`、`ui`、`game`、`diagnostics`。

初始化顺序：能力检查 → 渲染器 → 基础材质 → 布局与交互规则 → 可操作对象和初始状态 → UI/音频解锁 → 必要着色器预热 → 首个可操作画面。昂贵生成按时间片安排，显示实际进度。AudioContext 必须兼容用户手势解锁。

每帧：输入 → 游戏状态 → 固定或半固定步长模拟 → 动画/特效 → HUD → 反射/阴影等前置渲染 → 主场景 → 后期。限制补帧次数避免卡顿螺旋；暂停/失焦不能让模拟时间突然跳跃。测试帧时间用真实时钟，不能用钳制后的模拟 dt。

## 程序化几何

用结构参数保存模型：尺寸、轮廓、部件关系、重复间距、颜色和种子。细节分三个层次：远处轮廓、中距离结构、近距离表面。近景交互物与玩家反复观察的物体分配更多几何与材质预算。

倒角用于产生可读高光；法线贴图负责微小起伏，不能替代轮廓和大尺度凹凸。检查负缩放、法线方向、切线、缝隙、浮空和错误包围盒。碰撞形状应更简单，但必须与视觉边界一致到可接受程度。

同一栏杆/螺栓/箱子复用几何；空间重复优先实例化，静态独特结构按区域和材质合并。动态对象、透明对象、骨骼对象分别处理。远景结构降低细分，不把高面数近景资产无限复制。

## 程序化材质

生成配方应有物理因果，而不只是均匀噪点：

| 材质 | 配方 | 常见失败 |
|---|---|---|
| 涂漆金属 | 大块漆色 + 边缘损耗 + 少量露底 + 锈蚀向下流淌 | 每个表面同等生锈，画面脏乱 |
| 混凝土/沥青 | 大尺度色差 + 骨料 + 接缝/裂缝 + 局部污渍 | 所有尺度都用同一种噪声 |
| 湿地/水洼 | 地势遮罩 + 连续湿度 + 降低粗糙度 + 法线扰动 + 反射 | 全地面镜面、黑色水洞 |
| 橡胶/织物 | 低金属度 + 高粗糙度 + 细微有方向纹理 | 与金属反光完全一样 |
| 机械发光件 | 有面积的发光表面 + 受控亮度 + 必要的局部光 | Bloom 吞没物体轮廓 |

同一种表面使用共享基础纹理，实例颜色/种子/世界空间宏观噪声打散重复。避免为每个物体生成一套 2K 纹理。主要材质默认 512–1024；2048 仅在预算允许且近景证明确有收益时使用。

让表面留下与使用方式相符的痕迹。比如旋钮经常接触的外缘会被磨亮，路面低处会积水。一处磨损或湿润可共用一张强度遮罩，分别驱动底色、粗糙度和微小起伏。潮湿但仍粗糙的路面只出现宽而模糊的高光，有连续水膜的地方才逐渐显出清晰倒影。

多张贴图表现同一处损伤时，让底色、粗糙度、金属度和由磨损高度生成的法线对准同一表面位置。程序化遮罩可共用 UV、比例和偏移，法线的切线基也使用其采样坐标。合并静态箱体时可以在合并后的顶点上按面写一次投影 UV，让标准材质直接复用。片元着色器做三向投影时，各通道共用投影权重，先将各轴采到的法线转到同一坐标系再混合。移动道具用随物体移动的坐标，转动时检查磨损是否跟着表面。

生成 albedo 时保持一致的线性/sRGB 处理；normal 与 ORM 是数据，不能应用 sRGB 解码。法线需归一化，检查绿通道方向。为平铺纹理提供周期噪声或无缝边界；为图集加边距并验证 mipmap 下的串色。

细网和刻度线接近一个像素时，先检查 mipmap 缩小时的覆盖率。对着色器生成的细线或微法线，可用 `fwidth` 估计纹理在一个屏幕像素内的跨度，逐渐减弱无法分辨的频率。把图案放到实际游玩距离，沿会经过它的路线移动，看细线是否交替消失、高光是否跳动。平面作品也可在缩放时简化装饰线并保留可操作的刻度。

存储预算和显存预算分别计算：RGBA8 约为 `width × height × 4` 字节，完整 mip 链再乘约 4/3；RGBA16F 基础像素约 8 字节。多采样缓冲、深度附件、立方体六面、反射和后期中间目标另算。Three.js 的 `info.memory.textures` 是对象数量，不是显存字节。

## 光照与后期

1. 主光确定结构，环境光补足暗部。灯光数量受预算控制。
2. 用阴影和 AO 增强接触感；避免双重过暗。阴影范围按实际可见区域拟合，检测 acne、漏光与悬浮阴影。
3. 房间和室外的照明差异明显时，可在静态场景布置好后从房间内捕获环境。在 Three.js 中用 `CubeCamera` 捕获六面，再用 `PMREMGenerator.fromCubemap()` 预过滤，并把结果分给室内反光材质。把首次捕获计入加载预算，主要布景或照明变化时再更新。需要映出附近物体的水面可另用低分辨率平面反射，移动相机检查方向和裁剪平面。
4. 雾和体积散射营造距离层次。禁止浓雾遮住所有问题却让目标不可辨认。
5. 曝光、色调映射、Bloom 先单独调，再组合；颗粒、色差、暗角从接近零开始。提供减少镜头晃动和动态模糊的选项。

在固定机位制作“基础光照、加材质、加反射、最终后期”消融图。画质收益必须能在图上解释，避免盲目增加 pass。

## 声音与动画

声音配方：脉冲/白噪声 → 频段滤波/调频 → 包络 → 多层叠加 → 标准化/限幅 → 缓存 → 位置/遮挡/室内混响。重复动作的声音可用少量确定性变体区分力度、材质或速度。不要逐帧合成整段音频，限制同时发声数，避免 AudioBuffer 泄漏。

程序动画配方：以关节曲线、弹簧或事件时间线表现核心动作，例如车体侧倾或机关咬合。暂停、重开或切换状态时清理残留事件，并检查动画与规则判定同步。

## 内容规模与质量分配

先做一段完整流程，例如一条短赛道、一组逐步展开的谜题或一次生产周期，把几何和材质预算优先分给玩家反复观察的内容。用户要求更大内容量时明确增加的制作与包体成本，不能用重复方块填充后称开放世界。

合适的渲染等级示例：低档关闭 AO/平面反射、降低体积采样和内部像素；中档启用半分辨率 AO/反射；高档提高阴影与特效。低档仍保留主光、基础 PBR、任务辨识和反馈。

## 预算失败时的优先级

包体失败：检查内联 base64、大依赖、无用命名空间、重复生成器、调试信息、source map。共享生成规则、按使用导入、去掉无用代码；不能删除许可证或悄悄外移资源。

帧率失败：先分 CPU/GPU 瓶颈，检查分辨率、多 pass、透明 overdraw、反射重复绘制和阴影；再处理高频 AI、分配/GC 和 draw calls。不要只减面数。

视觉失败：先解决尺度、构图、光照与材质一致性，再调后期。优先修复浮空、穿透、过曝、反射错位、明显平铺和目标不可见。
