# 2.0.0

- 增加以玩家目标、参考品质样板和实际体验为起点的设计流程。
- 增加问题 → 假设 → 失败回归 → 修改 → 对比 → 回归 → 规则沉淀的闭环。
- 单 HTML、入口之后零额外网络请求成为明确硬约束，增强真实浏览器请求与尝试审计。
- 增加逐次动作与实际主画面提交关联，防止扣弹/伤害掩盖反馈缺失；动态画面必须单独审查。
- 增加 3 次冷启动、5 次重开、60 秒战斗、300 秒持续运行、对象池复用和帧节奏变体要求。
- 最终审查增加玩家体验证据；P0/P1 未解决、旧构建证据、缺少修改前后/回归均不能过关。
- 保留 v1 结果和限制；没有把旧游戏或新测试器反例结果冒充 v2 游戏质量认证。
